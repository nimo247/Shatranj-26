# Shatranj: Digital Ledger
**A Real-Time, Offline-First Megagame Economy Engine**

## Overview
Shatranj is a custom-built, full-stack application designed to run an in-person, 10-team megagame centered around resource management, economic trading, and strategic diplomacy. It replaces manual spreadsheets and physical tracking with a real-time, sub-millisecond spot-market trading ledger designed to handle high-volume player-to-player trades over a local network.

## Entities
* **The Imperial Citadel (Admin)**: The Game Master. Operates in God-Mode, can launch Custom Disasters, assign Cards, override trades, inject stimulus, and control the round step-clock.
* **Participant Teams (1-10)**: Factions mapped to 10 distinct geographical regions. Teams build infrastructure (Cards), suffer from Crises (Disasters), and trade Resources (Food, Material, Gold) on a live bilateral market.
* **Cards (Infrastructure)**: Constructable assets that require one-time build costs and recurring maintenance, but generate net yield each round. *Elite* cards offer powerful returns and are mathematically shielded from global disasters.
* **Custom Disasters**: Dynamic debuffs configured by the Admin to simulate economic shocks, enforcing flat inventory wipe caps (maxCap) or sustained percentage production penalties.

## Directory Structure
* 📂 **client/**: React 19 + TypeScript + Vite frontend. Contains the Participant Trading Terminal and the God-Mode Admin Dashboard.
* 📂 **server/**: Node.js + Express backend. Handles the Socket.IO real-time engine and atomic Prisma/SQLite database transactions.
* 📂 **docs/**: Comprehensive game design reference and operation manuals (Architecture, Rules, Cards, Disasters).
* 📂 **scratch/**: Safe sandbox preserving historical migration scripts and utility patches.

## Architecture
Shatranj is a **Single-Port Monorepo**. The Express backend concurrently serves the REST APIs, the WebSocket (`Socket.IO`) layer, and the statically compiled React frontend. This eliminates CORS issues and dramatically simplifies live-event networking.
* **Database**: SQLite with Write-Ahead Logging (WAL) for atomic concurrency and safe, rapid file-level backups.
* **Engine**: Tick-less trade execution. P2P Orders enforce strict Escrow locking to mathematically prevent double-spending race conditions.

## Installation & Local Setup
To run Shatranj locally on your machine for development or testing:

1. **Clone the repository:**
   ```bash
   git clone https://github.com/nimo247/Shatranj-26.git
   cd Shatranj-26
   ```
2. **Install all dependencies:**
   ```bash
   npm run setup
   ```
   *(This custom script automatically installs client and server dependencies, and pushes the database schema).*
3. **Start the application:**
   ```bash
   npm run dev
   ```
   *(This starts both the frontend and backend concurrently).*
4. **Access the Application:**
   * Participant Login: `http://localhost:3000/`
   * Admin Dashboard: `http://localhost:3000/admin` (Requires `.env` setup with `ADMIN_KEYWORD`).

## Event Day: Offline Execution Guide

Because Shatranj is designed for large auditoriums with unreliable internet, it is built to run 100% locally. 

### 1. The Wi-Fi Router Setup
1. Bring a standard home Wi-Fi router to the event. **It does not need to be plugged into a modem or the internet.**
2. Connect your Host Laptop (the server) to the router's Wi-Fi network.
3. Have all 10 Participant tablets/laptops connect to the exact same Wi-Fi network.

### 2. Launching the Engine
On the Host Laptop, open a terminal in this repository and run:
1. `npm run setup` *(if it is a fresh clone)*
2. `npm run dev` *(this starts both the server and client concurrently)*

*(Note: For maximum production performance without hot-reloading, you can build the client and run 
`npm start` instead, serving everything purely through the backend).*

### 3. Finding the Host IP
1. On the Host Laptop, open a Command Prompt and type ipconfig (Windows) or ifconfig (Mac).
2. Look for the IPv4 Address under your Wi-Fi adapter (It will usually look like 192.168.1.x or 10.0.0.x).

### 4. Running the Game
1. **Admin Access:** On the Host Laptop, open your browser to http://localhost:3000/admin. Log in using your ADMIN_KEYWORD (defined in your .env file). Use this dashboard to distribute credentials, assign starting cards, and manage the game state.
2. **Participant Access:** Tell the 10 teams to open their browsers and navigate directly to the Host's IP address (e.g., http://192.168.1.5:3000). They will log in using the credentials generated by the Admin.

### 5. Returning the Router to Normal (Post-Event)
Once the event concludes, simply shut down the Node server (Ctrl + C) in your terminal and disconnect your laptop. 
**No special configuration was injected into the router.** It functioned purely as a local LAN switch. To return the router to normal home use, just plug it back into an active modem and it will instantly provide internet access again.
